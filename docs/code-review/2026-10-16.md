# Code review — 2026-10-16

Branch `code-review`, cut from the end of `overnight-docs` (documentation pass). Base for both:
tag `pre-docs` (`f6cd17a`). Reviewer: Claude, unattended overnight; nothing here was run against
the real Meraki API.

## Summary

The tool is small, readable and well tested at the helper level, and the lookup logic did the
right thing end to end against a local fake Meraki API. The review found **four real bugs**, two
of which are visible to users (a documented MAC pattern that never matched, and a missing Uplink
flag in CLI output), plus **two security holes in the web UI** (reflected/stored XSS in the
topology page, and a WebSocket that any website could read) and a **CI gate that has never
checked anything**. All seven are fixed here with tests where the code allows one.

The larger open themes are not bugs but decisions: the web server has no authentication and
hands the `.env` API key to anything that can reach it; the CLI and web lookups are two diverging
copies of the same loop; the version number lives in four disagreeing places. Those are listed as
questions.

Counts: **8 fixed**, **19 found and not fixed**, **12 questions**.

## Fixed

Line numbers are on branch `code-review`.

1. **`pkg/macaddr/macaddr.go:75` — bracket ranges in MAC patterns never matched.**
   `NormalizePatternInput` stripped every `-` as a separator, so `[1-4]` became `[14]` and `[0-f]`
   became `[0F]`. The README's own example `08:f1:b3:6f:9c:[1-4][0-f]` matched almost nothing
   (`…:2a` did not match; `…:10` did, by accident). Fix: keep `-` inside brackets, strip it
   elsewhere. Verified: new cases in `TestBuildMacMatcher` (`macaddr_test.go:192`, `:205`) failed
   before and pass after; against the fake API, `--mac 'aa:bb:cc:00:00:0[0-3]'` returned nothing
   with the old binary and two rows with the new one. Affects CLI and web.

2. **`main.go:637` — CLI did not flag AGGR uplinks found in the live MAC table.** That branch
   looked up the `AGGR/0` ID itself in the uplink set; the other two CLI branches and the web path
   use `isPortUplink`, which also checks the member ports. Fix: use `isPortUplink` there too.
   Verified against the fake API (AGGR/0 with member 49 marked uplink): Uplink column empty before,
   `yes` after. No unit test: the branch lives inside `main()` and can't be called in isolation
   (see Found #1).

3. **`web_handlers.go:284` — reflected XSS on `/topology`.** Nine query parameters were pasted into
   `<meta content="…">` with `strings.NewReplacer`, whose comment claimed it "handles safely" — it
   does no escaping. A `hostname` such as `"><script>…` ran in the page. Fix: `html.EscapeString`
   each value (the browser unescapes the attribute, so `topology.js` reads the same values).
   Verified: `TestHandleTopology_EscapesQueryValues` (`web_test.go:32`) failed before, passes after.

4. **`static/js/topology.js:43` — stored XSS in the topology tooltip.** The tooltip was built with
   `innerHTML` from device names, model, type, port and hostname. Hostnames can come from a
   client's own DHCP request, so any device on the network could inject markup. Fix: an `esc()`
   helper identical to `app.js`'s `_esc`, applied to every interpolated value. Verified: `node
   --check`, and `esc()` exercised in node on a hostile string. Not exercised in a browser (the
   server opens the system browser on start, which I avoided overnight).

5. **`web.go:353` — any website could read the live log stream.** The WebSocket upgrader accepted
   every `Origin`. Browsers let any page open a WebSocket to `localhost`, so a page you visit while
   the UI is running could read every log line (MACs, IPs, hostnames). Fix: drop the custom
   `CheckOrigin` so gorilla/websocket's default same-origin check applies; `app.js` connects to
   `location.host`, so the UI is unaffected. Verified: `TestHandleWebSocketLogs_RejectsCrossOrigin`
   (`web_test.go:55`) — cross-origin handshake succeeded before, is refused after; same-origin
   still connects.

6. **`main.go:767` — fatal error messages were treated as format strings.** `log.Errorf(msg)`
   mangles any `%` in the message (Meraki error bodies, URL-encoded names): `100%d` printed as
   `100%!d(MISSING)`. Fix: `log.Errorf("%s", msg)`. Verified: `TestExitWithError_PercentInMessage`
   (`main_test.go:513`, re-executes the test binary because `exitWithError` calls `os.Exit`)
   failed before, passes after.

7. **`copyright_test.go:47`, `:125` — the GPL-header and no-inline-CSS/JS gates checked nothing.**
   `filepath.WalkDir(".")` visits `.` first; its name starts with `.`, so the "skip hidden
   directories" rule skipped the whole tree. All three tests have passed vacuously since they were
   added. Fix: never skip the root; fail if zero files were checked (`:91`, `:158`); exempt
   `_test.go` files from the inline-asset check (the test file itself names the needles, and the
   new XSS test sends one as input). Verified: with the guard alone, all three tests failed ("no
   .go files were checked"); after the fix they pass, and a scratch file without the header and
   with an inline style block made two of them fail as intended. Every existing file has the
   header.

8. **`build.ps1:108` — BuildTime was local time labelled UTC.** `Get-Date -Format "…Z"` prints
   local time with a literal `Z`; on this Mac that was 7 hours off. Fix:
   `(Get-Date).ToUniversalTime().ToString(…)`, matching `build.sh` and the Makefile. Verified in
   pwsh against `date -u`.

Also, readability: **`static/js/app.js:208`** now URL-encodes `orgId` like every other parameter.

## Found, not fixed

1. **CLI and web lookups are two copies of one loop** (`main.go` ~390–700 vs.
   `resolve.go` `processSwitchesForResolution`). They have already drifted (Fixed #2; the CLI
   applies `--switch`/`--port`, the web path doesn't; logging differs). Merging them is a refactor
   that changes structure across files — not surgical. Recommend doing it deliberately, with an
   end-to-end test against a fake API (the one used tonight is ~50 lines of Python).
2. **IP-mode hostname is silently discarded** (`main.go:376`). `resolvedMAC, _, resolvedHostname,
   err := …` declares a *new* `resolvedHostname` inside the `if`, so the outer one used at
   `main.go:485` ("pre-set in IP mode") is always empty. Not fixed because fixing it changes which
   hostname is shown — see Question 3.
3. **Every network failure is swallowed in the web resolve** (`web_handlers.go:176`). A bad key,
   a rate limit or an unknown org all show as "No devices found". See Question 4.
4. **`time.Sleep` ignores context** (`pkg/meraki/client.go:382`, `:473`, `:477`; `main.go:565`;
   `resolve.go:421`). Polls and retries can't be cancelled; a closed browser tab keeps a web
   resolve running for up to `MERAKI_MAC_POLL × 2 s` per switch. Behaviour change; low priority.
5. **`resolveDevices` ignores the request context** (`context.Background()` in `resolve.go`), for
   the same reason.
6. **Static files are served from `./static/` relative to the working directory** (`web.go:125`).
   A `go install`ed binary, or one started from another folder, serves a blank UI. `embed.FS`
   would fix it. See Question 7.
7. **D3 is loaded from `https://d3js.org/d3.v7.min.js`** (`web_handlers.go:277`) with no version
   pin beyond major 7 and no Subresource Integrity hash; the topology page also embeds the API key.
   A compromised CDN response could read the key. Vendoring a pinned copy, or adding `integrity=`,
   would close it.
8. **The OUI lookup caches failures forever** (`oui.go:57`–`67`). api.macvendors.com's free tier
   rate-limits at about one request a second; a "Resolve" over All Networks can fire many lookups,
   and every rate-limited OUI then shows no manufacturer until restart. The cache is also unbounded
   and keyed by caller input, and the OUI is inserted into the URL path unescaped (`oui.go:55`;
   fixed host, so no SSRF beyond that path).
9. **`handleWebSocketLogs` leaks its writer goroutine until the next log line** (`web.go:377`):
   when the client goes away, the loop only notices on its next write. Minor.
10. **`WriteText` measures widths in bytes** (`pkg/output/writers.go:107`), so non-ASCII names
    misalign. Cosmetic.
11. **`FetchArpMap` re-implements MAC normalisation** (`pkg/meraki/client.go:395`) instead of
    `macaddr.NormalizeExactMac`; it also accepts invalid MACs as keys. Harmless today.
12. **Dead code in `pkg/meraki`**: `BuildUplinkPortSet` (`:810`), `LLDPCDPData` (`:950`),
    `SwitchPortFull` (`:724`) are unused leftovers of the LLDP/topology uplink approach. Exported,
    so removal is an API change for a package nobody else imports. See Question 9.
13. **`ResolveIPToMAC` takes an unused `orgID`** and is the only method with receiver `c`
    (`pkg/meraki/client.go:994`). Readability only; changing the signature touches both callers.
14. **`handleValidateKey`/`handleGetNetworks` errors** use `http.Error` with a JSON body, which
    sets `Content-Type: text/plain`; API failures are returned as status 200 with `{"error"}`.
    `app.js` depends on the latter, so left alone.
15. **`--verbose` prints a `DEBUG:` line to stdout** (`main.go:223`) ahead of CSV/HTML output,
    which corrupts captured output. See Question 5.
16. **`build.sh` installs golangci-lint by piping the `master` branch `install.sh` to `sh`**
    (`build.sh:54`): unpinned remote code. `build.ps1` and `release.sh` skip lint when it's
    missing instead.
17. **`build.ps1` writes `.\findmac.exe` literally on macOS/Linux** — a file named `.\findmac.exe`
    in the repo root (git-ignored by `*.exe`). Windows-only script; noted, not changed.
18. **`make test` says "with race detection" but runs without `-race`** (Makefile header now says
    so). CI and `release.sh` use `-race`.
19. **CI is far behind the toolchain**: tests Go 1.21–1.23 and `golangci-lint` `latest`
    (unpinned), while this machine runs Go 1.26.7 and golangci-lint 2.14.0. Both passed locally;
    CI itself was not run (nothing pushed).

## Questions for Kent

1. **Web server authentication.** `/api/config` returns the `.env` API key in clear text and
   `/topology` embeds it; `/api/topology` and `/api/debug/network` use it for anyone who asks. Fine
   on `localhost`, dangerous with `--web-host 0.0.0.0`. Options: (a) refuse non-loopback
   `--web-host` without an explicit `--i-know` flag, (b) a random per-run token in the URL the
   browser is opened with, (c) leave it and rely on the README warning. **Recommend (b)** — it
   also stops other local processes and DNS-rebinding pages.
2. **API key in query strings** (`/api/networks?apiKey=…`, `/topology?apiKey=…`): it lands in
   browser history and any proxy logs. Move to a header/POST body? **Recommend yes**, together
   with Q1.
3. **IP-mode hostname** (Found #2): should `--ip` rows show the hostname from the IP resolution
   (reverse DNS first, then Meraki client data — what the web UI does and what the code comment
   intends), or keep today's behaviour (Meraki client data first, then `HOST_OVERRIDES`, then
   reverse DNS)? **Recommend matching the web UI** (a two-line fix), unless you rely on Notes
   winning.
4. **Web "All Networks" errors** (Found #3): return the first error (or a per-network error list)
   when *every* network fails? **Recommend yes**: today an expired key looks like "not found".
5. **`--verbose` stdout line** (Found #15): send it to stderr or drop it? **Recommend stderr.**
6. **One version number.** Makefile says `1.2.0`, `build.sh`/`build.ps1`/`release.sh` say
   `1.3.1`, CI injects `1.0.0`, `CHANGELOG.md` has a `1.3.2` (the `--env` feature) with no tag,
   and lists 1.3.0 above 1.3.2. Which is current — 1.3.2? **Recommend** a single `VERSION` file
   read by all four, then tag.
7. **Embed `static/`** in the binary with `embed.FS` so the UI works from any directory (Found #6)?
   **Recommend yes**; it is also what makes `go install` usable for `--interactive`.
8. **`GoVersion` is hard-coded `go1.21`** and never injected. Use `runtime.Version()`? **Recommend
   yes** — it changes `--version` output to the real toolchain.
9. **Remove the dead `pkg/meraki` code** (Found #12)? **Recommend yes.**
10. **`--port` substring matching**: `--port 3` matches 13, 23, 33, `AGGR/3`. Intended (it is
    tested) or should a bare number match exactly? **Recommend exact match for all-digit filters**,
    substring otherwise.
11. **`test-live-clients.ps1` hard-codes serial `Q2DY-HRFF-L8UJ` as the default** — a real
    device serial in a public repo, and its help says it prompts when it never does. Replace the
    default with `""` so it prompts? **Recommend yes.**
12. **Tracked `coverage` file** at the repo root (one line, `mode: atomic`) looks like a stray
    test artefact (`coverage.txt` is ignored; `coverage` is not). Delete and ignore it?
    **Recommend yes.**

## How to test this branch

```sh
git switch code-review
go vet ./... && go test -race ./... && golangci-lint run ./...
go run . --mac '08:f1:b3:6f:9c:[1-4][0-f]' --network ALL   # pattern now matches 08:f1:b3:6f:9c:10–4f
go run . --mac <a MAC you know sits behind an AGGR uplink>  # Uplink column should say yes
go run . --interactive                                      # from the repo root
```

In the UI: resolve something, open **Topology**, hover nodes (tooltips still render, hostnames
shown as text), and confirm the **Logs** panel still streams. To see the XSS fix, open
`http://localhost:8080/topology?hostname=%22%3E%3Cb%3Ex` — the page should show no bold text.
